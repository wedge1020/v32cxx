# v32c++ Gap Report

Findings from transpiling a Space Invaders OOP skeleton (single inheritance, virtual dispatch, operator overloading, friend classes, freestanding — no standard library) through v32c++. Each item notes the stage that rejects it, the workaround used, and a suggested development action.

Legend: **P** = parse-time (parser.y / lexer), **S** = semantic (sema.c), **L** = lower/codegen (lower.c / codegen.c), **V** = Vircon32 C target constraint, **W** = worked around in test program.

## Lexical gaps


| #   | Gap                                                                | Stage | Symptom                                              | Workaround used                                               | Suggested action                                                      |
| --- | ------------------------------------------------------------------ | ----- | ---------------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | `static` keyword (members and free functions)                      | P     | Lexer has no `static` token — immediate syntax error | Namespace-level globals/enums + free functions                | Add `STATIC` token and grammar rule; even parse-and-ignore would help |
| 2   | `explicit` keyword                                                 | P     | Syntax error                                         | Removed                                                       | Low priority; parse-and-ignore is sufficient                          |
| 3   | `unsigned` (and presumably `short`, `long`, signedness qualifiers) | P     | Only `int/float/void/bool/char` builtins exist       | Plain `int` RNG state                                         | Add unsigned builtins or at least accept-and-ignore the qualifier     |
| 4   | Class-nested enums and nested classes                              | P     | No rule                                              | Enums hoisted to namespace level (`EntityState`, `GameState`) | Support nested enum decls inside class scope                          |

## Confirmed working (regression baseline)

These constructs transpile cleanly today and make a good regression suite:

- Single inheritance with base-class ctor init (`: Entity(px, py, w, h)`) in init lists
- `virtual` methods + virtual dispatch through vtables, incl. overriding in subclasses (`Alien` → 3 row classes overriding `spriteForFrame`)
- Virtual destructors: in-body `virtual ~Entity() {}` (`func_header: '~' TYPE_NAME '(' ')'` composed with `opt_virtual`) and out-of-line `Class::~Class() {}`
- `new T(args)`, `new T[N]`, `delete p`, `delete[] p` (note: `delete[]` currently lowers identically to `delete` — no per-element dtor calls, per your own ast.h comment)
- Operator overloading: `operator+ - * == != += -= []` on a class; returning `*this` by reference
- Overloaded free functions and overloaded member functions (`collidesWith` ×3)
- `friend class Game;` (with the #16 caveat)
- 2D member arrays (`Alien* mGrid[5][11]`) — declaration via `array_bracket_list`, chained subscript `mGrid[r][c]` via left-recursive `postfix_expr '[' expr ']'`
- `static_cast` and the C-style cast family tokens exist; ternary, bitwise ops, compound assignments, `const` member functions
- Namespaces, typedefs, unions, enums; out-of-line method definitions
- Default construction of unmentioned class-typed fields in ctor init lists (relies on this for `Entity::mPos`, `Swarm::mOffset`, `Bullet::mVel`)
- Non-trivial global object construction (`Random g_rng;` namespace-level global with custom ctor)

## Prioritized development suggestions

1. **Class-typed member initializers (#9)** — highest ergonomic impact for idiomatic C++; every value-style class currently needs setters or a default ctor + `reset()`.
2. **Diagnose silently-dropped default member initializers (#8)** — a silent miscompile; even a warning would surface latent bugs.
3. **Forward declarations (#6) + friend-after-definition (#16)** — together they remove the fragile declaration-ordering constraint.
4. **Pure virtual `= 0` (#5)** — sema already builds vtables; parser support is small.
5. **Stacked `*&` (#7)** and **bare `T(args)` expressions (#10)** — small grammar additions.
6. **Sema check for multi-word by-value params/returns (#12)** — turn bad generated C into a clear error.
